# AGENTS.md

Guidance for AI coding agents working in this repository. Humans: see [CONTRIBUTING.md](CONTRIBUTING.md)
and the [README](README.md).

## What this is

`tauri-plugin-reactive` is a Tauri v2 plugin that exposes Rust **sources** to webviews, typed end to end:

- **States** (`ReactiveState<T>`) and **streams**, which the frontend subscribes to.
- **Writable states**, which the frontend can `set`.
- **Sinks**, which carry values from the frontend into Rust.

It ships as two packages from this one repo, versioned together:

- **Rust crate** `tauri-plugin-reactive` (`src/`, `build.rs`, `permissions/`)
- **npm package** `tauri-plugin-reactive-api` (`guest-js/`), the TypeScript client plus React/Vue/Angular adapters

## Repository layout

```
src/
  lib.rs            plugin init, ReactiveExt, page-load / window-destroyed hooks
  registry.rs       Reactive: source registration (state/stream/sink), typegen entry points
  state.rs          ReactiveState<T> (tokio watch wrapper)
  subscriptions.rs  subscription pump tasks, ownership, panic handling
  sinks.rs          frontend->Rust sinks: SinkStream, abort/close semantics, AbortOutcome
  scope.rs          SourceScope (ACL scope), glob matching, allow/deny checks
  pages.rs          per-webview generation counter, page tokens, closed-window tombstones
  commands.rs       the 8 IPC commands
  typegen.rs        TypeScript generation (feature `typegen`, ts-rs 12)
  error.rs          Error + stable error codes
build.rs            COMMANDS list + scope schema -> permissions/autogenerated (committed)
permissions/        default.toml (the reactive:default set), sources.toml (allow-all per command)
guest-js/           index.ts (client), react.ts, vue.ts, angular.ts
tests-js/           vitest tests with mocked IPC
examples/           npm workspace: react/ svelte/ vue/ angular/ + shared/{backend,frontend,scripts,icons}
```

## Commands

Run from the repo root unless noted. All of these should pass before you consider a change done.

```sh
# Rust (set CARGO_PROFILE_DEV_DEBUG=0 to keep target/ small; a full debug build is several GB)
cargo test -p tauri-plugin-reactive                       # without typegen
cargo test -p tauri-plugin-reactive --features typegen    # with typegen
cargo clippy --workspace --all-targets                    # must be warning-free
cargo package --allow-dirty -p tauri-plugin-reactive      # crate packages and builds standalone

# TypeScript client
npm install
npm test                 # vitest
npm run typecheck        # includes @ts-expect-error type-level tests in tests-js/
npm run build            # emits dist-js/ (gitignored)

# Examples (from examples/)
npm install
npm run lib              # REQUIRED after changing guest-js/: rebuilds, reinstalls, clears dev-server caches
npm run build -w reactive-example-react      # also: -svelte (svelte-check), -vue (vue-tsc), -angular
npm run selftest:react   # end-to-end self-test in the real app (also :svelte :vue :angular)
npm run selftest:dev -w reactive-example-react   # same under `tauri dev`
cargo test -p reactive-example-backend      # fails (and regenerates) if sources.gen.ts is stale
```

A self-test prints `N/N passed` and `SELF-TEST PASSED`. The runner exits 0 only on PASSED with no FAILED,
no timeout and, in built mode, a zero app exit code.

## Invariants: do not break these

These were established through repeated adversarial review. Each has tests. Preserve them when you
change nearby code.

**Permissions**
- Every command checks the source against capability scopes.
  - Opening, reading and writing (`subscribe`, `get`, `set`, `sink_open`) require an allow match and no deny match.
  - Id-based commands (`unsubscribe`, `sink_push`, `sink_close`, `sink_abort`) check only deny scopes,
    against the source recorded at open, and only act on the **calling webview's** own entries.
- Allow-everything scopes must be attached to **command** permissions (see `permissions/sources.toml`).
  A scope-only permission becomes a Tauri *global* scope, which applies to **every window** app-wide.
  That bug once made per-window restrictions meaningless.

**Sinks**
- A sink handler's stream ends with `None` **only** after `sink_close` (the frontend's `complete()`).
- Every other ending aborts the handler, so it never runs its post-loop "commit": abort, invalid value,
  reload, window destroy, and the registry being dropped.
- Abort order is always: set the `aborted` flag → `AbortHandle::abort()` → drop the sender (see
  `abort_entry`). `SinkStream::poll_next` re-checks the flag after `poll_recv`.
- `sink_abort` waits for the handler and reports what actually happened: `aborted`, or `completed` /
  `SinkFailed` if it had already finished on its own.

**Lifecycle**
- `subscribe` and `sink_open` take the page generation, record their entry, then re-check
  `pages.is_current`, and remove their own entry if a reload or window destroy happened in between.
- `retire` / `close_window` must run **before** entries are torn down.

**Client (`guest-js/index.ts`)**
- One canonical `Source` per name+args: WeakRef cache, args snapshotted, marked raw for Vue.
- Observer-object subscriptions follow Observable semantics. Callback/store-style subscriptions and
  `listen` persist across termination.
- An unhandled error is reported with `console.error` and never swallowed. A store-style callback
  doesn't count as handling it.
- `SinkWriter`: at most one `sink_push` in flight. `complete()` re-checks for an abort right before
  `sink_close`; once `sink_close` is sent, `abort()` is a no-op. A push failure aborts, except
  `SinkClosed`, which closes to collect the handler's own result.
- `SinkOutcome` is a thenable (not a native Promise) so that `await` can be detected. It must stay
  structurally assignable to `Promise<void>`.

## Conventions

- **Fix bugs with a regression test** that fails without the fix. For races and lifecycle fixes, prove
  it: temporarily remove the fix, confirm the test fails, restore it. Several tests here are stress
  tests built that way (e.g. `release_racing_a_busy_handler_never_commits`).
- **Adding a command:** add it to `COMMANDS` in `build.rs`, add the handler in `commands.rs` with a scope
  check, register it in `lib.rs`, decide whether it belongs in `permissions/default.toml`, and commit the
  regenerated `permissions/autogenerated/` files.
- **Public API changes:** update `README.md`, which documents every public Rust and TS API. Keep
  `Cargo.toml` and `package.json` versions equal.
- **Generated files:**
  - Never hand-edit `examples/shared/frontend/sources.gen.ts`. Change `register()` in
    `examples/shared/backend/src/lib.rs` and run `cargo test -p reactive-example-backend` (or any debug run).
  - Never commit `dist-js/`, `node_modules/`, `target/` or `src-tauri/gen/`.
- **Line endings:** `.gitattributes` stores LF.
- **Commit messages:** imperative summary line, a blank line, then the why.

## Git workflow (git-flow)

- `main` is releases only; `develop` is the default and integration branch.
- Work on `feature/<name>` or `bugfix/<name>` branched from `develop`, and merge back with `--no-ff`.
- Releases go through `release/<version>`; urgent fixes to released code through `hotfix/<version>`
  from `main`. Tags are `v<version>`. See [CONTRIBUTING.md](CONTRIBUTING.md).
- **Do not commit to `main` directly**, and don't push, tag, publish (`cargo publish` / `npm publish`)
  or change GitHub settings unless the user asked for it.

## Gotchas

- **Disk space:** Tauri debug builds are large. Use `CARGO_PROFILE_DEV_DEBUG=0`, and ask before deleting
  `target/` or other files you didn't create.
- **`tauri dev` restarts on any change under the repo** (the plugin is a path dependency).
  `.taurignore` keeps the watcher on Rust files. If you add files written during a run, ignore them there.
- **Stale client in `tauri dev`:** Vite and Angular pre-bundle dependencies and won't notice a rebuilt
  library with the same version. Always use `npm run lib` (from `examples/`) after changing `guest-js/`.
- **Angular dev server:** `@reactive-examples/shared` must stay in `prebundle.exclude` in
  `examples/angular/angular.json`.
- **Tauri finds plugin permissions only through an app's direct dependencies.** Each example's
  `src-tauri/Cargo.toml` therefore lists `tauri-plugin-reactive` directly, even though the shared backend
  also depends on it.
- **Mocking IPC in vitest:** mock `@tauri-apps/api/core`. In scratch projects outside the repo, mock the
  resolved module path, or the real `invoke` runs and tests pass vacuously.
- **TypeScript narrowing across `await`:** inside async methods, re-check mutable state through a method
  (see `SinkWriter.#isClosed`), not an inline comparison TS has already narrowed.
